## 一、项目结构：一个程序只能有一扇门

### ① 一个项目里塞了 12 个 .c，全都带 main（10-14）

**报错**（这是用两个文件实测出来的——我从没撞上，因为我一直用注释法躲着它）

```
b.obj : error LNK2005: main 已经在 a.obj 中定义
a.exe : fatal error LNK1169: 找到一个或多个多重定义的符号
```

**为什么**
一个项目最后要链接成**一个** `.exe`，而 `main` 是程序入口，等于一栋楼只有一扇大门。两个文件都写了 `main`，就是两扇门，链接器不知道该走哪个，直接报"多重定义"。

**我当时怎么躲过去的**
把其它 11 个文件的 `main` 全用 `//` 注释掉。（那个 up 主教的办法——能跑，但是**止痛药，不是治法**。）

**以后怎么办**
> **能自己独立跑起来的，就是一个项目。**

- 每写一道带 `main` 的练习题 → 新建一个项目（右键解决方案 → 添加 → 新建项目 → 空项目）
- 解决方案只建一次，能用四年；项目往里丢
- 10-14 已重构成 `my-c-learning.slnx` + 12 个项目，从此不用再注释任何 `main`

### ② 那把 main 全注释掉呢？

**报错**

```
LINK : fatal error LNK1561: 必须定义入口点
```

**记牢** `LNK2005` = 门太多；`LNK1561` = 没门。

## 二、字符 vs 数字：char 和 int 不是一回事（10-15）

### ③ char num7[100] = num1 % num2;

**报错**

```
error C2075: "num7": 初始化需要带括号的初始化表达式
```

**为什么**
我把"余数"当成字符串了。**我的推理链是**：字符串常量 `"..."` 里能写任何东西 → 那字符串变量里也能装任何东西 → 那余数就住进 `char[100]` 里吧。

**错在最后一步**：引号里写进去的是"**字**"，不是"**值**"。
`num1 % num2` 算出来的是一个**能拿去做算术的数字**，它该住 `int`，和 num3~num6 是一家人。`char[100]` 是"一排装字的格子"，塞数字进去，编译器就懵了。

**判据（背下来）**

> 这个东西，你会拿它做算术吗？
> - **会**（年龄、成绩、价格、数量、和差积商余数）→ 数字 → `int`（带小数用 `float/double`）
> - **不会**（名字、地址、一句话）→ 字 → `char` 数组

**正确写法** `int num7 = num1 % num2;`

### ④ 顺便搞清楚：char 到底是什么

| 写法 | 含义 |
|---|---|
| `char c = 'A';` | **单引号** = 一个字符 |
| `char s[] = "abc";` | **双引号** = 一串字符，末尾自动补一个看不见的 `\0` |
| `char a[100]` | 预留 100 个格子（99 个字 + 1 个 `\0` 哨兵） |

- `\0` 是**哨兵**：程序读到它，就知道"字符串到这儿结束了"
- 这也是为什么 `printf` 不用我报容量——它自己会读到 `\0` 停下

### ⑤ 屏幕骗过我一次：printf 是个翻译官

`printf("%d", 7)` 能印出 `7`，靠的**不是我准备了字符**，是 printf **自己把数字翻译成字**。

| 我写的 | 我其实在对 printf 说 |
|---|---|
| `printf("%d", 7)` | 这是**数字**，你负责翻译成字印出来 |
| `printf("%s", "abc")` | 这**已经是一串字**了，原样印就行 |

> **印出来的样子，不等于内存里的样子。**

## 三、scanf / printf 的格式符

### ⑥ printf 多给了一个参数（10-15）

**报错**

```
warning C4477: "printf": 格式字符串中传递的参数太多
```

**为什么** 我把 `scanf_s` 的"容量"搬到了 `printf` 里。

**判据（背下来）**

> **`scanf_s` 的 `%s` 要容量，`printf` 的 `%s` 不要。**

- `scanf_s` 是**往数组里写** → 得先知道最多写多少，写超了要溢出 → `scanf_s("%s", a, 100)`
- `printf` 是**从数组里读**，靠 `\0` 知道边界 → 不用报容量 → `printf("%s", a)`

### ⑦ scanf_s("%s", &a)

**现象** 程序什么也不输出就结束了 / 行为诡异。

**为什么** 两个错：
1. 少给了容量 → 正确的是 `scanf_s("%s", a, 100)`
2. 数组名前面多加了 `&` → **数组名本身就是地址**，不用加 `&`

**记牢**

> `%d` 要 `&`；`%s` 数组名**不加** `&`，但**要容量**。

### ⑧ scanf_s("%d,%d", ...) 里的那个逗号

**现象** 不报错，但输入的时候第二个数读不到，后面的结果全乱。

**为什么** 格式串里的**逗号是字面量**——输入的时候必须原样打一个逗号。

| 我输入 | 结果 |
|---|---|
| `7,2` | ✅ |
| `7 2`（空格） | ❌ 第二个数读不到 |
| `7` 回车 `2` | ❌ 同上 |

**改法** 写成 `"%d%d"`（中间空着就行）——因为 `%d` 会自动跳过空格、回车、Tab。

### ⑨ printf("%d\n,%d\n,", ...) 换行位置反了

**现象** 不报错，但输出错行，末尾还吊着一个孤零零的逗号。

**正解** `printf("%d %d\n", num3, num4);` —— `\n` 放最后，一次换一行。
（5 个结果还能一条打完：`printf("和=%d 差=%d 积=%d 商=%d 余=%d\n", ...);`）

## 四、编码：GBK 与 UTF-8

### ⑩ 中文在 GitHub 上乱码 / warning C4819

**现象**
- 本地 VS 里中文正常，推到 GitHub 变成乱码
- 编译时 `warning C4819: 该文件包含不能在当前代码页(936)中表示的字符`

**为什么** VS 在中文 Windows 上默认用 **GBK(936)** 保存；GitHub 只认 **UTF-8**。两边对不上就乱码。

**怎么根治（已做）**
- 项目根放 `.editorconfig`，写死 `charset = utf-8-bom`
- 但**已经存成 GBK 的旧文件不会自动变**——要打开另存、或者转换一次
- BOM 是给 VS 看的记号："这是 UTF-8，别猜了"

> 改编码这种事，改一次管一辈子——这就是 `.editorconfig` 的意义。

## 五、Git

### ⑪ 把终端提示符一起复制进命令

**现象** 命令报错，说找不到那个名字。

**为什么** 我把 `$ git status` 整行复制进去了——`$` 是**提示符**，不是命令的一部分。

> **只敲 `$` 后面那部分。**

### ⑫ fatal: not a git repository

**现象** 在新开的终端窗口敲 git 命令报这个错。

**为什么** 新窗口默认不在仓库目录里。

> 先 `cd` 到仓库目录；或者看提示符里有没有 `(main)`——有，才说明站在仓库里。

### ⑬ 以为 push 之后要去 GitHub 手动删旧文件（10-14）

**现象** 我在本地删了 12 个旧文件，担心 GitHub 上还留着，是不是要手动去删。

**真相** **不用手动删。** Git 记的不是"现在有哪些文件"，是"我改了什么"。
- 本地的"删除"是一条**改动记录**，`git add .` 会把它一起收走
- commit + push 之后，GitHub 上那些文件自动消失（显示成 deleted）
- 而且 **删掉 ≠ 消失**：旧版本还躺在历史里，随时能翻回来

> **Git 不是网盘，是版本历史。**

## 六、Linux / 虚拟机（为 RoboCup 环境学的，10-14）

### ⑭ sudo apt install -y curl 打成了 `- y`

**现象** 命令不认，吐一堆用法说明。

**为什么** `-y` 中间不能有空格，`- y` 会被当成两个参数。

> 选项和它的字母是一体的，不能拆开。

### ⑮ curl: command not found

**现象** 想下载东西，系统说没有 curl。

**这不是错**——这是 Linux 在告诉我："你要用的东西没装。"

**解决** `sudo apt install -y curl`
**意义** 这是我**第一次独立读懂** Linux 在说什么。

### ⑯ 装了增强功能（Guest Additions）却不生效

**现象** 装完还是不能复制粘贴、窗口不能自适应。

**为什么** 动了底层的东西 → **必须重启才生效**。

> 装完驱动 / 内核模块 / 增强功能 → **先重启**，别急着找 bug。
